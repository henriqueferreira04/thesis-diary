# Week of 10-19 to 10-25

## What I did

* Tried to read the AgentCards paper but had no access. Read the summary and example on the author's website instead. AgentCards is the agent equivalent of model cards: a way to describe agents, not to define them, so it is not what I am building.
* Read the AgentOps Pattern Catalogue (architectural patterns for safe and observable operations of foundation model based agents). It describes what an AgentOps platform should have to be safe and observable, which helps find gaps in the observability backend (MLflow).
* Read "Machine Learning Operations (MLOps): Overview, Definition, and Architecture". It clarified parts of MLOps I did not fully understand and where the platform sits in MLOps and in AgentOps. Wrote notes on the lifecycle and where the platform fits in `design/lifecycle-ownership.md`.
* Read the AgentOps survey (version 2). It defines AgentOps and proposes an operations framework with four phases (monitoring, anomaly detection, root cause localisation and resolution) across pre-execution, execution and post-execution. Anomalies are classified as intra-agent or inter-agent.
* Read "Securing Agentic AI" (ATFAA threat model with 9 threats in 5 domains, SHIELD with 6 mitigation strategies). Its first strategy, segmentation, recommends isolating agent components at the workload level, for example with Kubernetes Network Policies. It is conceptual, with no implementation or evaluation.
* Enforcement at infrastructure level was the theme with the fewest sources, so I added five candidate papers to the reading list.
* Read AgentBound (FSE 2026). It enforces declarative security policies on agent systems, including MCP servers, without changing the servers' code, using a monitoring mechanism to keep agents within the declared limits. It has an experimental evaluation.
* Notes on all papers are in `papers/read-already/`.

## Decisions

* AgentCards is related work at most, since it represents agents and does not define them.
* The platform fits the survey's framework as monitoring (injected traces) and as restricting the action space before execution (the topology enforced with NetworkPolicies). Detection, localisation and resolution are out of scope.
* Do not cite Table IV of the survey to compare tools: it says MLflow has no RAG metrics, which is not true.
* "Securing Agentic AI" is only cited as a position for segmentation, not as evidence.
