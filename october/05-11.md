# Week of 10-05 to 10-11

## What I did

* Compared OpenLIT with MLflow. OpenLIT is only observability (OpenTelemetry, injects instrumentation into pods), MLflow is the whole backend (runs, models, registry, traces). Idea: OpenLIT's instrumentation could feed MLflow, since MLflow accepts OTLP traces. Not tested, only read about.
* Clarified what "experiment" and "run" mean in MLflow for agents: there is no training, so an experiment is just a project label.
* Read the kagent docs and set up kagent in a Vagrant VM. Got a declarative agent and a BYO (own container image) agent running.
* Injected MLflow tracing into the BYO agent from outside, with no changes to the agent's own logic. Traces from different pods showed up as separate traces, so I linked them into one trace, also by injection.
* Built a multi-agent example with an enforced topology (network policy), then rebuilt it from the three roles of the spike because the first version was messy.
* Wrote the observability design notes (what to capture and why MLflow), made a first sketch and then v0.1 of the declarative file, and started the first sprint presentation (3 slides: title, motivation, work objectives).
* Started reading papers and sorted them: real papers in the reading list, tools (OpenLIT, kagent) in a separate note, with a reading order.

## Decisions

* Split the declaration in two files, as the professor indicated: one for the agents (completely declarative, no code) and one for the topology.
* kagent's declarative agent is a good base for the agent part of the file, but it does not cover traditional ML, observability settings or blocking routes between agents.
