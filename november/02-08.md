Sub-agents run in the same process as the parent, share its network, permissions and workspace, and can hand off to siblings that were never declared. So kagent 1.x isolates sessions but does not enforce relations between agents.

## Decisions

* kagent 0.10.x is no longer a candidate base, since it is a superseded line. It can still be an experimental baseline.
* Leaning towards kagent 1.x, using only part of it: separate Agents, session isolation and the egress gateway. The platform adds the Topology, a topology router (an MCP server with one tool per declared edge) and the EgressPolicies and NetworkPolicies around it. This depends on a short spike and on the supervisors.
* On 1.x, enforcement would move from network level to L7, with NetworkPolicies only around components outside kagent. The requirement stays the same (enforced in the infrastructure, outside the agent code), but the scope needs the supervisors' approval.
* Sub-agents inside a Topology node count as one node, with no enforcement between them.
* Kubeflow goes only in the state of the art. KServe is a possible option for the deploy stage.
